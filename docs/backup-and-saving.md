# 备份与保存

PlanBak 支持基于 `Manifest.db` 的本地 iOS 备份，包括未加密备份和密码已知的加密备份；不支持旧版 `Manifest.mbdb`。浏览和编辑的变更先保存在会话中，不会立即写入来源备份。若暂挂的编辑文件丢失，读取和保存会报错，不会静默使用原始内容。

## 原件与可编辑副本

- 未带有效副本标记的备份按来源处理。首次应用更改时，需要选择一个尚不存在的目标，创建副本后再保存。
- 有效的 `.planbak.json` 标记表示 PlanBak 创建的可编辑副本；后续应用更改可以直接写入该副本。
- 标记缺失、损坏或格式不受支持时，不把备份当作可直接写入的副本。标记不是防伪证明，也不能证明副本没有被其他软件修改。
- 新副本的目标不能与当前或会话中曾使用过的备份根目录重叠。
- 可以提前创建副本；此操作复制已保存的备份内容，不提前应用会话中的暂挂变更。

创建副本或首次应用更改时，输出在目标同级临时位置准备并在成功后发布。应用更改或创建副本进行时，数据层拒绝关闭会话；关闭开始后不接受新的保存、复制、传输或暂挂修改。直接应用到可编辑副本时，安装写入阶段不提供事务日志、回滚或崩溃恢复；异常终止或写入失败可能使副本不完整，应从保留的原始备份重新创建。

## 批量移动

来自不同文件夹的同名项目不能静默覆盖同一目标：选择保留两者时会生成不同名称，选择跳过时只移动其中一个；选择替换或未选择冲突策略时会报错并回滚整个操作。

## 内容与加密

清单按 domain 和相对路径索引文件，物理数据使用文件 ID 定位。加密备份读取时使用备份密码，新增或修改的数据重新加密；未修改数据保留现有内容。保存前会先检查输出仍需保留或移动的原始文件是否存在；被删除或由暂挂内容替换的旧文件不要求存在。最终输出仍会执行完整性检查。离线校验不能保证所有设备及 iOS 版本均可恢复。

新增普通文件默认使用保护类别 3，与 Apple 对未另行指定类别的第三方应用数据所述的默认类别一致。修改、移动或重命名已有文件时保留其原有类别；重新添加同一路径而沿用原条目时也保留原类别。保存修改后的文件时，若原类别缺失或无效，或者加密备份的 keybag 不含对应类别的密钥，会报错而不会悄悄更改类别。新增目录仍使用目录的元数据规则。

应用可能为特定文件指定不同于类别 3 的保护策略，程序无法从备份可靠推断其意图；该默认选择不保证符合每个应用的要求。

SQLite 查看器使用隔离的只读快照。若数据库使用 WAL 模式而备份中没有配套 WAL 文件，查看器会提示结果仅包含主数据库文件中可读取的内容。

工作区、图片缓存和外部编辑副本可能包含解密后的数据，正常关闭时清理。成功拖出的临时文件会留到关闭备份，避免接收程序尚未读取时被删除。
